# Site v2 Implementation Plan, part 2: event hubs, Teams explorer, compare pages, workflows, cutover

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Part 1 (`2026-10-16-site-v2-part1.md`) must be complete first: its loaders, layout, components and `check_site.py` are used here.

**Goal:** Finish the v2 site: one hub template for Play-In, Swiss, Knockouts and the Demacia Cup test; the Teams grid with filters and sorting; scouting-report team pages; a static compare page per pairing; the workflows building Astro; cutover and retirement of the old page.

**Architecture:** All pages are static Astro routes reading `data/dash/*.json` through `site/src/lib/data.ts`. Two small client scripts only: the Teams grid filter/sort (vanilla JS on data attributes) and the compare page pickers (two `<select>`s that navigate). Hubs share `EventHub.astro`; team and compare pages use `getStaticPaths`. The bracket, series-detail and Swiss-table rendering is ported from `dashboard/index.html` lines 636 to 750 (predictions script) into Astro components with the same data rules.

**Tech Stack:** as part 1. Workflows: `actions/setup-node@v4` with Node 24.

**Spec:** `docs/superpowers/specs/2026-10-16-site-v2-design.md` (Event hub, Demacia Cup hub, Teams grid, Team page, Compare page, Build and deploy, Error handling).

## Global Constraints

Same as part 1: repo root `worlds2026_bundle/worlds2026/`, branch `main`, NO commits or pushes by builders (the head commits), `python -X utf8`, baseline sha OK after every task, `url()` for every link, dd/mm/yyyy and NZDT, no em dashes, UNKNOWN never guessed, missing optional data renders a short line and never fails the build. Team slugs are lower-cased codes. Compare slugs are `<a>-vs-<b>` with `a < b` by code (`gen-vs-hle`, never `hle-vs-gen`; the other order 301s are not possible on Pages, so pickers always produce the canonical order).

## Review Focus

- Play-In rematch: the final can repeat a round-1 pairing; results must be matched to predictions by id AND pair, never by pair alone (Task 5 test uses a fabricated results file with KC beating C9 in R1 and C9 winning the final).
- A staged set that has not run yet (no `swiss` rows for set `swiss`): the hub shows the frozen baseline with the note "Not re-run yet; showing the frozen baseline", never an empty table (Task 5).
- Demacia Cup with `dcgi.json` missing: the hub renders its banner and "Check not run yet." (Task 5 build with the file temporarily renamed).
- Compare page for a pairing with no history: "Never met in 2025 or 2026." and no empty table (Task 8 test on CFO v LOS).
- Teams grid with JavaScript off: all 19 cards visible in rank order (the script only hides or reorders); filters are progressive (Task 6).
- `/teams/compare/` with no pairing: a picker page that defaults to the top two teams (Task 8).
- Day boundary without a data commit: "Today" and the "In play" flags are computed at build time. Task 5 adds `site/public/js/clock.js` (every series row carries `data-start` as an ISO UTC time; on load the script marks rows whose start has passed and relabels the Today card from the client's NZDT date) and Task 9 makes the Update workflow publish once a day even with no new results (a `publish=yes` when the NZDT date differs from the last deploy stamp in `data/dash/overview.json` `exported_nz`).

### Task 8: Compare pages

**Files:**
- Create: `site/src/pages/teams/compare/index.astro`, `site/src/pages/teams/compare/[pair].astro`, `site/src/components/CompareRow.astro`, `site/src/lib/compare.ts`, `site/public/js/compare-pick.js`

**Interfaces:**
- `compare.ts` exports `pairs(): { a: string; b: string; slug: string }[]` (171, `a < b`), `metrics(a, b): Group[]` where `Group = { title: string; rows: Row[] }` and `Row = { label: string; left: number | string | null; right: number | string | null; fmt: 'pct1' | 'pct0' | 'int' | 'signed' | 'min' | 'num1' | 'text'; higherIsBetter: boolean | null; verdict: string }`. Groups and rows, in order:
  1. Model: rating (`elo`), reach knockouts (`p_advance` live), Swiss 3-0 (`swiss` baseline `p30`), title odds live (`p_champion`).
  2. 2026 season (`team_season`): win rate (with record in the verdict), blue side win rate, red side win rate, GD@15, first blood, dragon share, baron share, average game (higherIsBetter null).
  3. Lanes: five rows, one per role, left and right being `"<player> · KDA <kda> · GD@15 <gd15> · KP <kp>%"` text with the better KDA marked in the verdict.
  4. Champion pool overlap: pool depth each; shared champions = champions in both teams' `team_season.picks` (names), listed in the verdict as `ChampIcon` chips in the page (pass the list separately as `shared: string[]`); "Fearless note: in a Bo5 every champion picked by either side is gone for the rest of the series, so shared comfort picks are contested early."
  5. Head to head: rows from `h2h()` for the pair (date, tournament and stage, score oriented to the pair), a record line "2026: A x, B y (series); 2025 internationals: ..." and "Never met in 2025 or 2026." when none.
  The verdict string is computed, not opinion: e.g. "GEN +66" for ratings, "GEN +6.2 points" for percentages, "about the same" when the gap is under 1% of the larger value or under 0.5 points, and the summary strip values: `p_bo1/p_bo3/p_bo5` from `matchups()` for the pair.
- `[pair].astro`: `getStaticPaths` from `pairs()`; header cards (logo, name, "REGION seed N · rank R · tier T", roster line from the dossier), VS, swap chips (the ten highest-ranked other teams for each side, linking to the canonical slug), the Bo1 / Bo3 / Bo5 switch (three pre-rendered summary strips, inline script shows one), summary strip (win chance in that format for each side, live title odds, rank), then the five groups as `CompareRow`s with bars scaled to the larger value and the leading side in gold. No verdict box.
- `compare/index.astro`: two `<select>`s (all 19 teams) and a Go button; `compare-pick.js` navigates to `url('teams/compare/<min>-vs-<max>/')`; the page body shows the default comparison of the top two teams below the pickers.
